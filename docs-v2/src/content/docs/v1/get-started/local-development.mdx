The Anchor framework streamlines the process of writing, testing, and deploying Solana programs. This guide walks through creating a new project, iterating on it locally, and deploying it to a public cluster.

## Prerequisites

Before you begin, ensure you have Rust, the Solana CLI, and the Anchor CLI installed. See the [Installation](/docs/v1/get-started/installation/) page for step-by-step instructions.

## Getting started

<Steps>

<Step>

### Create a new project

To start a new project, use the `$ anchor init <dim><project-name></dim>` (for our examples, we will use `my-project` for `<dim><project-name></dim>`). This creates a new directory with the specified name and scaffolds a default program and test file. By default, Anchor generates a modular program structure to promote better code organization and maintainability:

<FileTree>
  <Dir name="programs">
    <Dir name="my-project">
      <Dir name="src">
        <Dir name="instructions" comment="Instruction handler implementations">
          <File name="increment.rs" />
          <File name="initialize.rs" />
        </Dir>
        <File name="constants.rs" comment="Program constants" />
        <File name="error.rs" comment="Custom error definitions" />
        <File name="instructions.rs" comment="Instructions module root" />
        <File name="lib.rs" comment="Main entry point" highlight />
        <File name="state.rs" comment="Account state module root" />
      </Dir>
      <Dir name="tests">
        <File name="test_initialize.rs" comment="Default LiteSVM test" />
      </Dir>
    </Dir>
  </Dir>
</FileTree>

`lib.rs{:file}` is the program's entry point. It declares each submodule and wires instruction handlers into the `#[program]{:rs}` block. The `declare_id!(){:rs}` value is your program's on-chain address (by default, the public key of the keypair at `/target/deploy/my_project-keypair.json{:file}`).

```rust
pub mod constants;
pub mod error;
pub mod instructions;
pub mod state;

use anchor_lang::prelude::*;

pub use constants::*;
pub use instructions::*;
pub use state::*;

declare_id!("3ynNB373Q3VAzKp7m4x238po36hjAGFXFJB4ybN2iTyg");

#[program]
pub mod my_project {
    use super::*;

    pub fn initialize(ctx: Context<Initialize>) -> Result<()> {
        crate::instructions::initialize::handle_initialize(ctx)
    }

    pub fn increment(ctx: Context<Increment>) -> Result<()> {
        crate::instructions::increment::handle_increment(ctx)
    }
}
```

```rust
use anchor_lang::prelude::*;

use crate::{constants::*, state::Counter};

#[derive(Accounts)]
pub struct Initialize<'info> {
    #[account(mut)]
    pub payer: Signer<'info>,
    #[account(
        init,
        payer = payer,
        space = 8 + Counter::INIT_SPACE,
        seeds = [COUNTER_SEED],
        bump
    )]
    pub counter: Account<'info, Counter>,
    pub system_program: Program<'info, System>,
}

pub fn handle_initialize(ctx: Context<Initialize>) -> Result<()> {
    ctx.accounts.counter.count = 0;
    ctx.accounts.counter.authority = ctx.accounts.payer.key();

    let cpi_accounts = anchor_lang::system_program::Transfer {
        from: ctx.accounts.payer.to_account_info(),
        to: ctx.accounts.counter.to_account_info(),
    };
    let cpi_ctx = CpiContext::new(anchor_lang::system_program::ID, cpi_accounts);
    anchor_lang::system_program::transfer(cpi_ctx, HELLO_WORLD_LAMPORTS)?;

    msg!("Hello, world! Counter initialized");
    Ok(())
}
```

### Test file

Anchor generates a Rust test that runs the program in [LiteSVM](/docs/v1/testing/litesvm/), an in-process Solana VM. It is located at `/programs/my-project/tests/test_initialize.rs{:file}`, loads the compiled program, then sends the `initialize` and `increment` instructions and checks the counter account. To test with TypeScript instead, pass `<dim>--test-template</dim> mocha` or `<dim>--test-template</dim> jest`. Other Rust options are `<dim>--test-template</dim> rust` ([Rust client](/docs/v1/clients/rust/)) and `<dim>--test-template</dim> mollusk` ([Mollusk](/docs/v1/testing/mollusk/)).

```rust title="programs/my-project/tests/test_initialize.rs"
use {
    anchor_lang::{
        prelude::Pubkey,
        solana_program::{instruction::Instruction, system_program},
        AccountDeserialize, InstructionData, ToAccountMetas,
    },
    litesvm::LiteSVM,
    solana_keypair::Keypair,
    solana_message::{Message, VersionedMessage},
    solana_signer::Signer,
    solana_transaction::versioned::VersionedTransaction,
};

#[test]
fn test_initialize() {
    let program_id = my_project::id();
    let payer = Keypair::new();
    let counter = Pubkey::find_program_address(
        &[my_project::constants::COUNTER_SEED],
        &program_id,
    )
    .0;
    let mut svm = LiteSVM::new();
    let bytes = include_bytes!(concat!(
        env!("CARGO_TARGET_TMPDIR"),
        "/../deploy/my_project.so"
    ));
    svm.add_program(program_id, bytes).unwrap();
    svm.airdrop(&payer.pubkey(), 1_000_000_000).unwrap();

    let instruction = Instruction::new_with_bytes(
        program_id,
        &my_project::instruction::Initialize {}.data(),
        my_project::accounts::Initialize {
            payer: payer.pubkey(),
            counter,
            system_program: system_program::ID,
        }
        .to_account_metas(None),
    );

    let blockhash = svm.latest_blockhash();
    let msg = Message::new_with_blockhash(&[instruction], Some(&payer.pubkey()), &blockhash);
    let tx = VersionedTransaction::try_new(VersionedMessage::Legacy(msg), &[&payer]).unwrap();

    let res = svm.send_transaction(tx);
    assert!(res.is_ok(), "send_transaction failed: {:?}", res);

    let counter_account = svm.get_account(&counter).unwrap();
    let mut data: &[u8] = &counter_account.data;
    let counter_state = my_project::state::Counter::try_deserialize(&mut data).unwrap();
    assert_eq!(counter_state.count, 0);
    assert_eq!(counter_state.authority, payer.pubkey());

    let instruction = Instruction::new_with_bytes(
        program_id,
        &my_project::instruction::Increment {}.data(),
        my_project::accounts::Increment {
            counter,
            authority: payer.pubkey(),
        }
        .to_account_metas(None),
    );

    let blockhash = svm.latest_blockhash();
    let msg = Message::new_with_blockhash(&[instruction], Some(&payer.pubkey()), &blockhash);
    let tx = VersionedTransaction::try_new(VersionedMessage::Legacy(msg), &[&payer]).unwrap();

    let res = svm.send_transaction(tx);
    assert!(res.is_ok(), "send_transaction failed: {:?}", res);

    let counter_account = svm.get_account(&counter).unwrap();
    let mut data: &[u8] = &counter_account.data;
    let counter_state = my_project::state::Counter::try_deserialize(&mut data).unwrap();
    assert_eq!(counter_state.count, 1);
    assert_eq!(counter_state.authority, payer.pubkey());
}
```

</Step>
<Step>

### Build the program

Run `$ <blue>anchor</blue> build` to compile the program. The compiled artifact is written to `/target/deploy/my_project.so{:file}`. This binary is the executable bytecode uploaded to the chain during deployment.

</Step>
<Step>

### Test the program

Run `$ <blue>anchor</blue> test` to execute the test suite.

With the default LiteSVM template, this builds the program and runs `$ cargo test`. The test loads `/target/deploy/my_project.so{:file}` into LiteSVM, so no validator is started and nothing is deployed: the generated `Anchor.toml{:file}` sets `skip_local_validator = true` and `test = "cargo test"`.

With a TypeScript template (`<dim>--test-template</dim> mocha` or `jest`), the `Anchor.toml{:file}` targets `localnet`, and `$ <blue>anchor</blue> test` starts a local validator, builds and deploys the program, runs the tests in `/tests{:dir}`, then shuts the validator down.

<Callout variant="tip" title="Persistent validator for debugging (TypeScript templates)">
  To keep the validator running between iterations so you can inspect accounts and transaction logs
  on the [Solana Explorer](https://explorer.solana.com/?cluster=custom) while developing, start `${' '}
  <blue>solana-test-validator</blue>` in a separate terminal. From there, pass `
  <dim>--skip-local-validator</dim>` to `$ <blue>anchor</blue> test{' '}
  <dim>--skip-local-validator</dim>` so tests attach to the running instance instead of spawning
  their own.
</Callout>

</Step>
<Step>

### Deploy to Devnet

By default, the `Anchor.toml{:file}` config file in an Anchor project specifies the localnet cluster. To deploy your program to devnet, change the `cluster{:toml}` value to `"Devnet"{:js}`:

```toml title="Anchor.toml" showLineNumbers add={12} del={11}
[toolchain]

[features]
resolution = true
skip-lint = false

[programs.localnet]
my_program = "3ynNB373Q3VAzKp7m4x238po36hjAGFXFJB4ybN2iTyg"

[provider]
cluster = "Localnet"
cluster = "Devnet"
wallet = "~/.config/solana/id.json"

[scripts]
test = "yarn run ts-mocha -p ./tsconfig.json -t 1000000 tests/**/*.ts"
```

<Callout variant="important" title="Funding the deploy wallet">
  Deploying to devnet requires your wallet to have enough SOL to cover the deployment cost. You can
  get devnet SOL using the [Web Faucet](https://faucet.solana.com/).
</Callout>

Run `$ <blue>anchor</blue> program deploy` to push the program to the cluster specified in `Anchor.toml{:file}`. The `$ <blue>anchor</blue> test` command also respects this setting.

To deploy to mainnet, update the `Anchor.toml{:file}` file to specify the mainnet cluster:

```toml title="Anchor.toml" add={3} del={2}
[provider]
cluster = "Devnet"
cluster = "Mainnet"
wallet = "~/.config/solana/id.json"
```

</Step>
<Step>

### Update the program

Solana programs are updated in place by redeploying a new build to the same program ID. After making code changes, run `$ <blue>anchor</blue> build` to produce an updated `.so{:file}` artifact, then `$ <blue>anchor</blue> program deploy` to upload it.

</Step>
<Step>

### Close the program

Closing a program reclaims the SOL allocated to its on-chain account. Run `$ solana program close <dim><program-id></dim>` to retire it:

```console
$ <blue>solana</blue> program close <dim><program-id></dim> --bypass-warning
```

The program ID is permanently retired once closed. You cannot redeploy to the same address.

</Step>

</Steps>
