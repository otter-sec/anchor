`1.1.1` is the first `1.1` feature release. Highlights include opt-in legacy IDL handlers, quieter `#[event_cpi]{:rs}`, OtterSec verified builds, and CLI build, path, and key improvements. The full list lives in the [`CHANGELOG.md{:file}`](https://github.com/otter-sec/anchor/blob/v1.1.1/CHANGELOG.md#111---2026-06-25).

---

## How to upgrade

### Common steps

1. Update Anchor crate(s) to `1.1.1`.

2. Update TS package(s) to `1.1.1`.

To install the new `anchor-cli` via AVM:

```console
$ <blue>avm</blue> install 1.1.1
```

Or directly from the repository:

```console
$ <blue>cargo</blue> install <dim>--git</dim> https://github.com/otter-sec/anchor <dim>--tag</dim> v1.1.1 anchor-cli <dim>--locked</dim>
```

## Recommended Solana version

The recommended Solana version is `3.1.10`, unchanged from `1.0.0`.

## Lang

### Fix `#[event_cpi]` deprecation warnings

`#[event_cpi]{:rs}` was making use of deprecated `AccountInfo{:rs}` accounts internally. This has been updated to use the recommended `UncheckedAccount{:rs}` instead, silencing the noisy warnings.

### Re-add the legacy IDL handlers

In `1.0.0`, we changed the mechanism for storing the IDL on chain from automatically generated instruction handlers to the [Solana Program Metadata Program](https://github.com/solana-program/program-metadata). This resulted in large binary size and security wins, but caused breakage for developers relying on this mechanism. This functionality has been re-added. You can opt in with:

```rust showLineNumbers=false
#[program(legacy_idl)]
pub mod my_program {
    // ...
}
```

And interact with it using `$ <blue>anchor</blue> legacy-idl`.

### Versioned transactions in `anchor-client`

The Rust `anchor-client` crate can build and send versioned transactions.

### MSRV and `syn` 2

`anchor-lang` requires Rust `1.89`. `anchor-syn` migrated from syn 1.x to syn 2.0, so IDL generation accepts modern Rust syntax that previously failed the build.

### CPI return `program_id` checks

CPI return values now verify the source `program_id{:rs}` before they are consumed, so a callee cannot plant return data under another program's identity.

## CLI

### Remove hard build error with mismatched keys

Previously, `$ <blue>anchor</blue> build` verified that the program's private keypair matched the `declare_id!{:rs}` pubkey. This was a pain point for developers collaborating on Anchor projects, as private keys would typically not be checked into version control.

This has been made into a soft error; the warning is still printed, but does not block builds. `--ignore-keys` can still be used to silence this.

### More reliable handling of relative paths

The CLI now performs more reliable normalization of input paths. This means that relative paths (including when invoking `anchor` in a subdirectory) will be handled more predictably.

### Optimized build times

Previously, the CLI built programs in a naive order, which resulted in bottlenecking on certain dependencies. The CLI will now attempt to be smarter when building packages, which can provide compile-time speedups of up to 50%.

### Custom target directories

Build, test, deploy, and IDL paths resolve the Cargo target directory through `cargo metadata`, so `CARGO_TARGET_DIR` and workspace-level overrides work instead of assuming `target/{:dir}`.

### Named scripts

`Anchor.toml{:file}` can define multiple named scripts. Run them with `$ <blue>anchor</blue> test <dim>--script</dim> <name>` or `$ <blue>anchor</blue> run <name>` (`r` is an alias for `run`).

### Historical IDL fetch

`$ <blue>anchor</blue> idl fetch-historical` recovers historical on-chain IDLs.

### Nested workspace guard

`$ <blue>anchor</blue> init` refuses to create a new Anchor workspace inside an existing Cargo workspace, which previously produced broken nested layouts.

## TypeScript

### OtterSec verified builds

`verifiedBuild{:ts}` now talks to the OtterSec registry (`verify.osec.io`) instead of the defunct `apr.dev` API.
